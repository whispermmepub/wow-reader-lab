# WoW Reader v64 — 100k Library and Incremental Cloud Sync Design

Date: 2026-09-18

## Goal

Make WoW Reader remain usable with 100,000+ library records and make cloud sync proportional to changed books rather than total library size, while preserving v63 data, package identity, Google/Firebase continuity, EPUB/PDF files, reading state and restore compatibility.

## Non-negotiable compatibility

- applicationId remains `com.whisper.wowreader`.
- minSdk 23 / targetSdk 36 / compileSdk 36.
- Existing v63 installs must migrate in place without clearing app data.
- Fresh install must initialize the same schema cleanly.
- Original EPUB/PDF bytes are never rewritten for metadata or cover changes.
- Legacy `wow_reader_backup_v1.zip` stays available as restore fallback.
- Production signing identity and Firebase Android identity stay unchanged.

## 100k library architecture

SQLite `ReaderStateDb` becomes the indexed source for library metadata, progress, shelves, annotation counts, cover state and sync state. Library UI uses COUNT + LIMIT/OFFSET page queries. RecyclerView keeps only bounded pages in memory, and cover extraction uses a bounded executor rather than one thread per card.

Normal Home/Library/Search/Sort/Filter/Shelves/Notes paths must not scan the entire library directory.

## Incremental Drive sync

Each EPUB/PDF is represented by a Drive object named from SHA-256 content identity. A dirty queue in SQLite selects small batches only. For example, 100,000 existing books plus 2 new books produces 2 book uploads, not a 100,002-book rebuild.

Large uploads use resumable sessions with persisted session URL and byte offset. Deletes use tombstones so another device cannot resurrect removed books.

Drive upload metadata does not use `properties` or `appProperties`; identity is encoded in the object name. DB v6 clears stale experimental resumable sessions on upgrade while keeping dirty work queued.

Reader state remains separate from book binaries. Legacy monolithic ZIP backup remains a compatibility fallback rather than the primary per-change upload path.

## Custom cover

Edit Book Details supports Title, Author and app-side custom cover. Device images are normalized/compressed; online search uses Google Books + Open Library with a browser Google Images fallback. Default display scope is Library Card Only; Everywhere is opt-in. Original EPUB/PDF content and file hash do not change.

## EPUB whole-book pages

Page mode shows cumulative whole-book `Page X / Y`. Counts are based on rendered chapter pagination and cached for the current layout fingerprint. Font, spacing, margin, viewport/orientation changes invalidate pagination and rebuild it. Reading position is preserved independently of page number.

## Failure handling

- Missing/corrupt custom cover falls back to original cover.
- Failed online search/download never replaces current cover.
- Sync interruption keeps the queue/checkpoint and retries safely.
- Expired resumable session restarts only that file.
- Upgrade migrations are additive and non-destructive.

## Verification gates

- Pure-Java 100k query/sync/page/cover/Drive metadata contract tests.
- Android debug/release compile and lint.
- Existing v63 update-install regression.
- Fresh-install regression.
- Production signer verification for sideload APK.
- Play AAB package/version/SDK/signing verification.
