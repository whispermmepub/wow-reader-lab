# WoW Reader v64 — Implementation Plan

1. Create isolated `v64-100k-sync` branch from stable v63.
2. Apply the already device-tested experimental changes directly to production source.
3. Set release candidate to versionCode 64 / versionName 2.20.0.
4. Persist 100k library indexing, shelves, progress, annotations, custom-cover and sync state in SQLite.
5. Replace normal whole-library UI scans with DB paging and bounded visual workers.
6. Enable per-book SHA-256 Drive objects, dirty batches, tombstones and resumable checkpoints.
7. Remove Drive properties/appProperties and migrate DB to v6, clearing stale resumable sessions only.
8. Integrate custom cover UI/search and whole-book EPUB page numbering.
9. Add pure-Java contract tests to the repository and run them in CI/release workflows.
10. Build/lint the branch, open PR, verify diff, then merge to main.
11. Build release APK + AAB from the merged source.
12. Sign the non-Play APK with the existing production signer and verify certificate digests.
13. Sign the Play AAB with the configured upload key if available; otherwise deliver the built AAB with signing status explicitly identified.
14. Verify package, versionCode/versionName, SDK levels, signer and SHA-256 checksums.
15. User performs both update-install and clean/fresh-install tests before Play rollout.
